# AGENTS.md

Guide for coding agents working **on** this repository: how the code is
organised and what must not break. Agents that **use** octlabels in another
project should read `docs/llms.txt` or the Claude skill in `skills/octlabels/`
instead; the user documentation is in `docs/` (MkDocs).

## What this is

octlabels defines two file formats for annotations of OCT scans and a Python
library (numpy, pyyaml, pillow) to read, write and process them:

- **Layers**: per-A-scan annotations of one B-scan in a YAML file `NNN.yml`
  (optionally `.yml.gz` / `.yml.xz`): layer boundaries (`Layer`, a height per
  A-scan), regions (`AScanRegion`, 0/1 presence per A-scan) and any per-A-scan
  properties (`confidence`, `uncertainty`, custom ones).
- **Lesions**: 2D masks of one B-scan bit-packed into an 8-bit indexed PNG
  `NNN.png`. Main lesions (mutually exclusive) are an ID in the low bits,
  overlays one flag bit each from bit 7 down; names and the bit split are JSON
  in a `zTXt` chunk `"Lesions"`.

A volume is a folder (or a `.zip` file) of these per-B-scan files. The format
specifications are `docs/formats/*.md`.

## Design rules

- **Layers and lesions are symmetric.** `LayerSet`/`LesionSet` and
  `LayerVolume`/`LesionVolume` share method names and parameters (`load`,
  `save`, `to_array(names)`, `from_array(..., names, info)`, `ensure`,
  `subset`, `copy`, `load_bscan`). A feature added to one kind is added to the
  other, or the asymmetry is deliberate and documented.
- **Alignment is enforced, not hoped for.** Every property of an annotation has
  exactly one entry per A-scan; `AScanAnnotation.set_property` and the `values`
  setter check it. Anything that changes the width creates new annotations
  through `map_arrays`, so values and all properties change together.
- **Transforms return copies** and go through `LayerSet.map_annotations`. Each
  array is resampled with `AScanAnnotation.interpolation(key)`: values of
  layers linear, region values nearest, `confidence` "min" (conservative),
  other properties by dtype. Transforms that change the pixel size update
  `lateral_resolution_um` / `axial_resolution_um` in `info`.
- **Volumes work on bytes.** `Volume._save_sets(target, suffix, to_bytes,
  zip_compression)` and `Volume._read_sets(source, from_bytes, only)` handle
  folders and zip files in one code path. A path ending in `.zip` means a zip
  file; everything else a folder.
- **New annotation kinds** in a `LayerSet` need an attribute in
  `LayerSet.__init__` and an entry in `LayerSet.SECTIONS` (file order).
- `layers/serialization.py` imports `layer_set.py`, so `LayerSet` imports
  serialization inside its methods to avoid a cycle.

## Compatibility that must not break

- **Existing files are written back byte-identical.** Loading and saving a
  layer file (except files whose old padding was misaligned) or a lesion PNG
  must reproduce the original bytes. Formatting lives in
  `serialization._rows/_format_cells/_scalar` and `packing.save_lesions`;
  change them only with that check (`OCTLABELS_TESTCASES`, below).
- **Both layer row styles are read**: comma-separated text (default) and YAML
  lists (`yaml_arrays=True`). An empty property row means "not stored".
- **`packing.save_lesions/load_lesions/save_lesion_dicts/load_lesion_dicts`
  keep their signatures**; users' scripts call them directly.
- Old keyword names (`layer_names`, `optional_info`, `uncertainty_array`) raise
  `TypeError` in `LayerSet.from_array` instead of becoming custom properties.

## Commands

```bash
pip install -e ".[dev]"            # library + pytest, ruff, black
pip install -e ".[docs]"           # mkdocs (<2), mkdocs-material, mkdocstrings
pytest                             # unit tests, docs examples (~1 s)
OCTLABELS_TESTCASES=/path/to/scans pytest   # also checks real data (slow)
ruff check src tests && black --check src tests
mkdocs build --strict              # fails on broken docstring cross-references
mkdocs serve                       # preview at http://127.0.0.1:8000
```

`OCTLABELS_TESTCASES` points to a folder of real scans (`*/layers/*.yml.xz`,
`*/lesions/*.png`); the data is not in the repository. Without it, those tests
are skipped.

## Conventions

- Readable over clever: plain loops instead of dense comprehensions, named
  inner functions instead of nested lambdas, no `# type: ignore` or
  `# noqa` to silence a design problem.
- Python ≥ 3.10, `from __future__ import annotations`, types from `typing`
  (`List`, `Dict`, `Optional`; ruff's UP006/UP007/UP035/UP045 are disabled for
  this). black and ruff with 88 columns.
- Google-style docstrings (`Args:`, `Returns:`, `Raises:`). Array shapes are
  written `Shape: [num_layers, width].` in docstrings and `# [layers, width]`
  in code comments.
- Cross-references in docstrings use mkdocstrings' scoped syntax,
  ``[`LayerSet`][]``, resolved like Python names in that module; fully
  qualified (``[`save`][octlabels.layers.serialization.save]``) only for names
  not imported there. Module constants are documented with a string literal
  directly after the assignment, not with `#:` comments.
- Errors are exceptions with messages that name the offending item; warnings
  use `warnings.warn` with a `stacklevel` pointing at the caller. No `print`.

## Tests and docs

- `tests/conftest.py` provides a `layer_set` fixture (2 layers with
  uncertainty and a custom property `snr`, plus one region).
- `tests/test_docs.py` runs every ```` ```python ```` block of every page in
  `docs/` (and of `llms.txt` and the skill) in order, against a generated sample scan `patient_01/` (layers ILM,
  RPE, BM and region DRUSEN; lesions IRF, SRF main and HRF overlay; 3 B-scans of
  128 × 64). Examples must run against that data. Mark a block that cannot run
  (needs torch, external files) with a line `<!-- skip-test: reason -->` above
  it. Output stated in comments (`print(x)  # 22.6`) should match.
- `docs/llms.txt` and `skills/octlabels/SKILL.md` summarise the public API.
  Update them with any change to it; their examples are run by
  `test_docs.py` too.
- Coverage is ~100 % of lines; new code comes with tests, including the error
  paths a user is likely to hit.
